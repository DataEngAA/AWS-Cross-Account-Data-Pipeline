# Data model

## Raw JSON file (Account A, S3)
One file contains a batch of scraped product records.

```json
{
  "source": "books.toscrape.com",
  "scraped_at": "2026-10-20T09:30:00Z",
  "records": [
    {
      "product_id": "p-00042",
      "name": "Sample product",
      "category": "Books",
      "price": 12.99,
      "currency": "GBP",
      "in_stock": true,
      "scraped_at": "2026-10-20T09:30:00Z",
      "url": "https://example.test/p-00042"
    }
  ]
}
```

Each record carries its own `scraped_at` (the batch value is copied onto every record), so DQ-05 can quarantine one bad record without failing the whole file.

Deliberate bad records for testing (generated by `src/generator/generate.py`, counts per file in `data/manifest.json`): missing `price`, negative `price`, invalid `scraped_at`, future `scraped_at`, duplicate `product_id`, empty `name`, invalid `currency`, null `category`. One extra file per run is not valid JSON, to test the fail-fast path.

Default volume: 30 files x 5,000 records (150,000 records, about 30 MB) over 7 days, drawn from a catalogue of 8,000 products so the same product appears on several days at a slightly different price.

## S3 layout
```
raw bucket (Account A)
  raw/source=<source>/date=YYYY-MM-DD/<run_id>.json

curated bucket (Account B)
  curated/products/date=YYYY-MM-DD/category=<category>/part-*.parquet
  quarantine/source=<source>/date=YYYY-MM-DD/<run_id>.json
  dq-results/date=YYYY-MM-DD/<run_id>.json
  athena-results/
```

## DynamoDB table `scrape_state` (Account A)
| Attribute | Type | Notes |
|---|---|---|
| `file_key` (partition key) | String | S3 object key |
| `status` | String | `RECEIVED`, `PROCESSED`, `FAILED` |
| `received_at` | String (ISO 8601) | when the file landed |
| `run_id` | String | Step Functions execution name |
| `source` | String | from the `source=` part of the key, e.g. `synthetic` |
| `s3_version_id` | String | S3 object version, used with the key to build an idempotent execution name |
| `record_count` | Number | records in the raw file |
| `valid_count` | Number | records that passed quality rules |

Access pattern: get and update one item by `file_key`. No scan needed for this project.

## RDS PostgreSQL table `products`
```sql
CREATE TABLE products (
  product_id  TEXT NOT NULL,
  scraped_at  TIMESTAMPTZ NOT NULL,
  name        TEXT NOT NULL,
  category    TEXT NOT NULL,
  price       NUMERIC(10,2) NOT NULL CHECK (price > 0),
  currency    CHAR(3) NOT NULL,
  in_stock    BOOLEAN NOT NULL,
  source      TEXT NOT NULL,
  loaded_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (product_id, scraped_at)
);
```

The composite primary key gives idempotency: loading the same file twice uses `INSERT ... ON CONFLICT DO NOTHING` (or an upsert) and creates no duplicates.
